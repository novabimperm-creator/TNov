Qwen в локальной сети

Как поднять в сети компании сервер с открытой моделью Qwen, чтобы сотрудники работали с Revit через Qwen Code, а данные моделей не уходили наружу.

Qwen3-Coder-30B-A3B vLLM / Ollama OpenAI-совместимый API

Схема

ПК сотрудника                                           Сервер в сети компании
Revit + TNov ◄── MCP, только localhost ──► Qwen Code ── HTTPS + ключ ──► nginx ─► vLLM или Ollama + модель Qwen
  • Коннектор TNov в Revit не меняется. Он слушает только 127.0.0.1 и [::1] на компьютере сотрудника, из сети недоступен.
  • Новая служба — только сервер модели. Он принимает запросы Qwen Code по OpenAI-совместимому API (/v1/chat/completions). Через тот же сервер может работать и Codex.
  • Данные не уходят наружу. Интернет серверу нужен только один раз — скачать модель и образы. Дальше он может работать без выхода в интернет.
  • Лицензия. Модели Qwen3 и Qwen3-Coder выпущены под Apache 2.0, коммерческое использование разрешено.

Железо и модель

Модель — Qwen3-Coder-30B-A3B-Instruct: 30,5 млрд параметров, на каждый токен работают ~3,3 млрд, поэтому она быстрая. Хорошо вызывает инструменты, а для коннектора это главное.

  • Сервер: Linux (Ubuntu 22.04/24.04), драйвер NVIDIA, Docker и NVIDIA Container Toolkit. Оперативной памяти от 64 ГБ, SSD от 100 ГБ под модели.
  • Контекст: нужно не меньше 32 тыс. токенов, лучше 64 тыс. Описания инструментов коннектора и ответы с данными модели Revit занимают много места. Контекст тоже расходует видеопамять, поэтому числа пользователей в таблице — ориентир для пилота, а не гарантия.
  • Цифры по памяти приблизительные. Перед закупкой проверьте их на пилотной карте.

Вариант А · vLLM (рекомендуется)

vLLM рассчитан на несколько одновременных пользователей и сам проверяет ключ доступа. Запуск в Docker на пилотной карте 24 ГБ:

export VLLM_API_KEY="$(openssl rand -hex 32)"   # сохраните ключ в хранилище паролей

docker run -d --name qwen-coder --restart unless-stopped \
  --gpus all --ipc=host \
  -p 127.0.0.1:8000:8000 \
  -v /srv/hf-cache:/root/.cache/huggingface \
  vllm/vllm-openai:<версия> \
  --model QuantTrio/Qwen3-Coder-30B-A3B-Instruct-AWQ \
  --served-model-name qwen3-coder \
  --api-key "$VLLM_API_KEY" \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --max-model-len 65536 \
  --gpu-memory-utilization 0.92
  • --enable-auto-tool-choice --tool-call-parser qwen3_coder — обязательно. Без них модель возвращает вызовы инструментов обычным текстом, и Qwen Code не сможет работать с Revit. Обычный парсер hermes для Qwen3-Coder не подходит.
  • Порт открыт только на 127.0.0.1. Наружу его отдаёт nginx с HTTPS (см. «Безопасность»).
  • Версия образа. Вместо <версия> укажите конкретную проверенную версию, а не latest: внутренние интерфейсы vLLM и парсеры меняются от версии к версии.
  • Другие карты. Для 48 ГБ — --model Qwen/Qwen3-Coder-30B-A3B-Instruct-FP8. Для двух карт добавьте --tensor-parallel-size 2. Для квантованной модели на нескольких картах может понадобиться --enable-expert-parallel.
  • AWQ-сборка QuantTrio/…-AWQ сторонняя (Hugging Face). Если политика требует только официальные веса, берите FP8-версию от Qwen и карту на 48 ГБ.

Вариант Б · Ollama (для пробы)

Проще в установке, но рассчитан на малую нагрузку и не умеет проверять ключ: доступ закрывается только через nginx.

curl -fsSL https://ollama.com/install.sh | sh

sudo systemctl edit ollama
# в открывшийся файл:
# [Service]
# Environment="OLLAMA_HOST=127.0.0.1:11434"
# Environment="OLLAMA_CONTEXT_LENGTH=65536"
sudo systemctl restart ollama

ollama pull hf.co/unsloth/Qwen3-Coder-30B-A3B-Instruct-GGUF:UD-Q4_K_XL
  • OLLAMA_CONTEXT_LENGTH задаётся именно в службе: переменная в своей консоли на службу не действует. Контекст по умолчанию — всего несколько тысяч токенов, с ним вызовы инструментов ломаются: модель отвечает пустотой или сырым JSON.
  • Сборка Unsloth выбрана потому, что в ней исправлены вызовы инструментов для Qwen3-Coder. Берите её или другую сборку, где эти исправления точно есть.
  • Адрес API для клиентов — /v1 за nginx. Имя модели — то, что показывает ollama list.

Безопасность

Сервер модели читает всё, что сотрудники отправляют из Revit: параметры, имена, сведения о проекте, изображения видов. Относитесь к нему как к файловому серверу с проектными данными.

  • Только HTTPS через nginx, сертификат внутреннего ЦС. Сама модель слушает только 127.0.0.1.
  • Ключ доступа. vLLM проверяет его сам (--api-key). Для Ollama проверку делает nginx (пример ниже). Ключ передавайте только через защищённый канал.
  • Фаервол: порт 443 открыт только для подсетей компании. Без доступа из интернета и из сегментов NetBird, где есть посторонние устройства.
  • Журналы. Не включайте запись содержимого запросов. Если она нужна для отладки, храните такие журналы как проектные данные и удаляйте после разбора.
  • Выход в интернет серверу после загрузки модели не нужен. Его можно закрыть.
server {
    listen 443 ssl;
    server_name llm.example.local;                 # имя сервера в сети компании
    ssl_certificate     /etc/ssl/llm/fullchain.pem;
    ssl_certificate_key /etc/ssl/llm/privkey.pem;

    location /v1/ {
        # Только для Ollama: у vLLM ключ проверяет сам vLLM, этот if не нужен.
        if ($http_authorization != "Bearer ВАШ_КЛЮЧ") { return 401; }

        proxy_pass http://127.0.0.1:8000;          # vLLM; для Ollama — 127.0.0.1:11434
        proxy_http_version 1.1;
        proxy_buffering off;                       # потоковые ответы
        proxy_read_timeout 900s;                   # долгие ответы модели
        client_max_body_size 50m;                  # изображения видов в запросах
    }
}
sudo ufw allow from 192.168.0.0/16 to any port 443 proto tcp   # подставьте подсети компании
sudo ufw deny 443/tcp
sudo ufw enable

Проверка

С любого компьютера в сети компании:

curl -s https://llm.example.local/v1/models -H "Authorization: Bearer ВАШ_КЛЮЧ"

В ответе должна быть модель qwen3-coder (или имя из ollama list). Без ключа сервер должен вернуть 401. Проверка, что модель вызывает инструменты:

curl -s https://llm.example.local/v1/chat/completions \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" -H "Content-Type: application/json" \
  -d '{"model":"qwen3-coder","messages":[{"role":"user","content":"Сколько стен в модели?"}],
       "tools":[{"type":"function","function":{"name":"count_walls","description":"Количество стен в модели Revit",
       "parameters":{"type":"object","properties":{}}}}]}'

В ответе должно быть поле tool_calls с вызовом count_walls. Если вместо него текст с XML или JSON внутри content, проверьте параметры парсера инструментов (vLLM) или сборку модели (Ollama).

Что передать BIM-менеджеру

  • Адрес API: например, https://llm.example.local/v1.
  • Имя модели: qwen3-coder (или из ollama list).
  • Ключ доступа — только через защищённый канал.
  • Сертификат внутреннего ЦС, если его ещё нет на рабочих станциях: иначе Qwen Code не доверит HTTPS-соединению.

Когда сервер заработает, в плагин TNov будет добавлена автонастройка: адрес, модель и ключ задаются один раз в настройках коннектора на сетевой папке TNov, а кнопка в Revit прописывает подключение Qwen Code у сотрудника. До этого Qwen Code у каждого настраивается вручную: /auth → свой OpenAI-совместимый провайдер → адрес, модель, ключ.

Прокси на рабочих станциях. Если на компьютерах стоит локальный прокси (Qwen Code берёт его из HTTPS_PROXY), имя сервера модели нужно добавить в NO_PROXY. Иначе запросы уйдут в прокси и до сервера не дойдут.

Ограничения

  • Качество. Локальная модель на 30 млрд параметров слабее облачных Claude и Codex: в сложных скриптах Revit API ошибается чаще, и ей нужно больше попыток. Простые задачи — поиск, подсчёты, марки, параметры — решает нормально. Защита модели в TNov (уровни доступа, проверка скриптов, отмена Ctrl+Z) работает так же.
  • Нагрузка. Одновременные запросы делят видеокарту: при нескольких активных пользователях ответы медленнее. Начните с пилота на одной карте и замерьте.
  • Обновления. Версии vLLM, Ollama и модели обновляйте вручную, после проверки на пилоте.
TNov · коннектор Revit — нейросети (MCP). Памятка по развёртыванию локальной модели Qwen. Команды проверены по документации vLLM, Ollama и Qwen Code на октябрь 2026 года; перед установкой сверьтесь с документацией вашей версии.
